## Bug hunt v0.15.2 (12.11.2026)

Четыре read-only ревью (меш+эталон, профи-съёмка, автосъёмка/Object Capture/фотограмметрия,
Python/CI) плюс собственный аудит. Из 29 находок подтверждены и исправлены 27; две отклонены
(см. «Что НЕ менялось»).

| Область | Было → стало |
|---|---|
| Эталон A4 как карта | поправка ×0,27 проходила проверку формы → `ReferenceRect.autoFactor` с пределами 0,65…1,55 и `Failure.implausibleScale` |
| Достоверность Vision | `observations.first?.confidence` → `best.confidence` |
| Глубина в углах эталона | бралась без `confidenceMap` → `RulerPicker.worldPoint(…, minConfidence: .medium)` |
| Медиана глубины | при чётном окне `sorted[n/2]` → среднее двух средних |
| Автосъёмка, покрытие | `markCovered` до съёмки: кольцо 100 % без кадров → только после успешного `capture` |
| Автосъёмка, главный актор | `Task` на каждый ARFrame, JPEG и запись на UI-потоке → каждый второй кадр |
| Автосъёмка, уход вкладки | shots.json не писался → `.onDisappear { stopScan() }` |
| Автосъёмка, «Заново» | писал метаданные бросаемого скана → удаляет пустую папку |
| Профи-серия | уход с вкладки оставлял папку без shots.json → `stop()` доводит до `finishBurst()` |
| Профи-серия | `shootNext()` без проверки сессии сжигал все слоты на ошибках → guard + «Съёмка прервана» |
| Профи-серия | `fileIndex += 1` до записи, `remaining -= 1` до затвора → счёт после успеха, «Снято N из M» |
| Профи-глубина | `try? raw.write` при ошибке, но `depthFile` в meta → `depthError` вместо ложного файла |
| Профи-экран | настройки живы во время серии → `.disabled(isCapturing)`, нет кнопки «Остановить» → есть |
| Профи-ошибки | отсутствие глубины шло в модальный алерт «Ошибка камеры» → баннер `depthWarning` |
| Срок профиля | `daysLeft` округлялся вниз: живой профиль в последние сутки → FAIL → `rounded(.up)` |
| Фотограмметрия | ZIP собирался на главном акторе → `Task.detached`, копия кадров в `photogram-input` внутри скана → во временную папку |
| Object Capture | сессия держала камеру после ухода, не было кнопки нового скана → `shutdown()` + «Новый» |
| LiDAR-меш | «Пауза» только обещала продолжение → `resume()` без сброса трекинга; `guard generation` от гонок; STL-ошибка не глушится |
| ZIP-выгрузка | архив целиком в память (OOM на больших сканах) → `Content-Length` + потоковая отдача чанками по 1 МБ |
| ПК: масштаб | ошибка масштаба молча давала «мм» из единиц COLMAP → `unscaled(reason)` с предупреждением |
| ПК: images.txt | строки POINTS2D парсились как камеры (`int("0.5123")`) → автомат по парам строк в `sfm_io` |
| ПК: стол | метрики окружности не входили в `ok` → `radius_ok`/`circle_ok`, печать по существующим ключам |
| ПК: дисторсия | SIMPLE_RADIAL терял k1, OPENCV_FISHEYE путал k3/k4 с p1/p2 → таблицы в `sfm_io._params` |
| ПК: точность | экран габарита показывал 0,1 мм при сыром LiDAR 1–2 см → «±5 мм после калибровки» |
| Скрипты iOS | любой ненулевой код → «не установлено»; `readline` игнорировал `--seconds`; `anchor_path_check` импортировал несуществующий модуль → исправлено |

## Что НЕ менялось (сознательно)

- `VNDetectRectanglesRequest.maximumAspectRatio` вернулся к 1.0: Vision считает соотношение
  «короткая/длинная» (всегда 0…1), значение 3.0 ломало бы валидацию запроса. Ориентация эталона
  проверяется в `ReferenceRect`, а не в запросе.
- Центр предмета для коуча по-прежнему берётся raycast'ом по плоскости стола: альтернатива
  (центр AABB меша) на старте пустая, а ошибка смещения компенсируется тем, что покрытие
  считается по направлениям, а не по точкам.

- **Алгоритм габарита** (`.scratch/testdata/smart_swift_emu.py`): 320 синтетических сцен,
  худшая ошибка 0.3–0.9 мм, пути TABLE/OBB размечаются правильно.
- **ZIP-писатель** (перенос на Python, `zipfile` читает, CRC совпадают), **STL** (63 684 байта
  = 84 + 50 × 1272), **разбор профиля подписи** (дата совпала с профилем, выданным Sideloadly).
- **ПК-часть**: `measure.py` (куб 100 мм → 1000 см³, `--smart` 60.01×40.32×100.29 при истине
  100×60×40, `--fit-mm`), `photogrammetry.py` (dry-run, резюм), `fetch.py` (мок-сервер,
  `--new-only`), `py_compile` всех скриптов.
