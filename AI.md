# Умный сканер: что реально стоит встраивать

Короткий ответ: **свою модель вшивать не надо**. Почти всё «ИИ», что нужно сканеру, уже лежит
в iOS и работает на нейродвижке A17 Pro бесплатно и без загрузок. Своя модель не даст выигрыша,
а стоит дорого: нужен Mac или coremltools (на этом ПК нет ни того, ни другого), веса надо откуда-то
качать (pypi и raw.githubusercontent заблокированы), и она съест память, которой и так мало.

## 1. Где уже есть ИИ (ничего не качаем)

| Что | Кто делает | Зачем сканеру |
|---|---|---|
| Реконструкция по фото | `PhotogrammetrySession` / Object Capture | превращает кадры в USDZ-модель, матчинг и мешинг делает Apple |
| Понимание сцены | ARKit `sceneReconstruction`, `sceneDepth` | меш, плоскости, глубина, классификация пол/стол/стена |
| Выделение предмета | Vision `VNGenerateForegroundInstanceMaskRequest` (iOS 17+) | маска «заметных объектов» → отрезать стол, фон, руки |
| Поиск квадрата | Vision `VNDetectRectanglesRequest` | автокалибровка по напечатанному квадрату известного размера |
| Салиентность/текст | Vision saliency, `VNRecognizeTextRequest` | «где объект», наклейки и подписи |

Это не «маленькие модели на подпорках»: Object Capture — та же фотограмметрия, что в Polycam,
только от Apple. Наш вклад — не сеть, а **логика вокруг**: когда снимать, что выбросить,
какому размеру верить.

## 2. Почему не своя модель

- **Нет смысла**: SAM/Depth Anything на телефоне решают задачу «выделить объект», которую Vision
  уже решает системной моделью с доступом к нейродвижку.
- **Есть цена**: 200–500 МБ в бандле (переподпись каждые 7 дней это переживёт, а вот память — нет),
  плюс A17 Pro делит 8 ГБ между ARKit, камерой и фотограмметрией.
- **LLM/VLM на устройстве — нет**: 8 ГБ RAM, нет весов, нет рантайма. Разговоры «пусть ИИ сам
  поймёт» здесь не про этот телефон.

## 2б. Инструменты: что проверено, а что нет

Первая редакция этого файла утверждала «собрать нечем, веса негде взять». Проверка 29.10.2026
показала, что верна только первая половина — и то с оговоркой.

**Сборка.** У `coremltools` на PyPI нет колёс под Windows: 9.0 публикует только
`macosx_*` и `manylinux1_x86_64`, а 8.3.0 — вообще лишь sdist. Поэтому `pip install coremltools`
на этом ПК собирает исходники и почти наверняка падает. Но:

- на Linux-раннере GitHub Actions колесо ставится штатно, и конвертация работает —
  `pc/convert_model.py` + workflow `convert-model` (проверено: прогон 40900034690, MIL-демо 1,7 КБ;
  прогон 40900140457, MobileNetV3 через `torch.jit.trace`, 5,0 МБ, `coremltools 9.0`);
- `Models/Model.mlpackage` коммитится в ветку `models` — забрать можно git-ом, как IPA из `builds`;
- в `.mlmodelc` модель компилирует Xcode на macOS-раннере при сборке приложения — руками ничего
  делать не нужно, macOS для этого шага у нас уже есть.

**Веса.** Проверено в ту же дату: `pypi.org` и `files.pythonhosted.org` отвечают, пакет скачался;
`huggingface.co` отдаёт `config.json` (200, 662 Б); LFS-блоб `pytorch_model.bin` скачался целиком
(2,5 МБ). `hf-mirror.com` теперь просто редиректит 308 на `huggingface.co`. По-прежнему заблокированы
`raw.githubusercontent.com`, `objects.githubusercontent.com`, `pipelines.actions.githubusercontent.com` —
но к весам это отношения не имеет.

Вывод: **путь «PyTorch → Core ML → бандл» существует и проверен**. Решение «не вшивать свою модель»
остаётся, но уже по делу (см. выше), а не из-за отсутствия инструментов.


## 3. Три уровня «умности»

**Уровень 0 — без моделей вообще (дешёвые сигналы, 60 кадров/с).**
- Коуч: «дальше/ближе», «медленнее», «мало текстуры», «пересвет», «этот ракурс уже был».
- Покрытие: 26 направлений на сфере вокруг объекта; показываем «обойдено 60 %».
- Автосъёмка: кадр берётся сам, если резкий, объект целиком в кадре, ракурс новый.
- Автофиниш: 2–3 круга и ≥60 кадров → сразу реконструкция.
- Метрики доверия к размеру: `coverage`, `planeShare`, сколько граней поддержало каждую ось.

**Уровень 1 — системные модели Vision (без загрузок, iOS 17+).**
- Отсечение фона: маска переднего плана на ключевых кадрах → точки меша, не попавшие в маску
  в большинстве кадров, выбрасываются. Убирает стол и фон, не трогая геометрию предмета.
- Автокалибровка: печатаем один раз лист с чёрным квадратом 100×100 мм, кладём рядом с объектом;
  Vision находит квадрат, глубина даёт его плоскость → мм на пиксель → `calibrationFactor`
  без штангенциркуля и без ручной линейки.
- Маска ещё и подсказывает «объект обрезан краем кадра» — повод отойти.

**Уровень 2 — своя нейросеть.** Не делаем (см. п. 2). Вернуться, если появится Mac:
тогда имеет смысл не SAM, а маленькая сеть «оценка пригодности скана к печати» на наших же данных.

## 4. UX: один экран, одна кнопка

Сейчас пять вкладок — это не «просто». Целевой поток:

1. Открыл → камера уже смотрит, внизу подсказка «положите предмет на стол».
2. Приложение само увидело плоскость и предмет, рисует рамку, говорит «медленно обходите».
3. Кадры идут сами; кольцо прогресса показывает покрытие и что осталось (верх/низ/бока).
4. Дошло до 100 % → «Модель собирается…» (прогресс Object Capture).
5. Итог: 3D-вьюер, габариты с пометкой доверия, кнопки «STL для печати», «Поделиться», «Переснять».
6. Всё сложное (ручные ISO, профи-фото, Wi-Fi-сервер, тест) — в «Ещё», не на первом экране.

## 5. Чего не делаем

- Не обещаем «ИИ сам поймёт форму» — форма берётся из геометрии, а не из фантазии модели.
- Не подгоняем размеры под «круглые» числа: для печати это вредит.
- Не отправляем сканы в облако (и без того: сеть нестабильна, данные — наше дело).

## 6. Порядок работ

| Версия | Что | Риск |
|---|---|---|
| 0.14 | автосъёмка + автофиниш + коуч (уровень 0) | низкий, API проверены |
| 0.15 | маска переднего плана → отсечение фона | средний: проекция точек, голосование по кадрам |
| 0.16 | автокалибровка печатным квадратом | средний: детект квадрата + плоскость |
| 0.17 | один экран вместо пяти вкладок | низкий, только UI |
| 0.18 | своя модель (только если полевые тесты покажут пробел) | средний: конверсия и веса уже проверены |

Каждый шаг проверяется локально: маска — на сохранённых кадрах с телефона, покрытие и коуч —
на синтетических траекториях, калибровка — на сгенерированных картинках с квадратом.
